# Revenue Metrics Analysis

## Project Overview

This project analyses revenue and paying-user activity for a digital product using PostgreSQL and Tableau Public.

The objective was to prepare a dataset for a revenue dashboard, calculate key monthly revenue metrics, and explore changes in revenue and user payment activity over time.

## Business Questions

- How does monthly revenue change over time?
- How many users make payments each month?
- How many users start paying in a given month?
- How does user churn affect revenue?
- How do revenue expansion and contraction contribute to monthly revenue changes?
- How can revenue metrics be used to monitor business performance?

## Key Metrics

The SQL analysis calculates the following metrics:

- **Monthly Revenue (MRR proxy)** — total recorded payment revenue for each month.
- **Paid Users** — number of unique users who made payments during a month.
- **New Paid Users** — users making their first recorded payment in a given month.
- **New MRR** — revenue generated by users making their first recorded payment in a given month.
- **Churned Users** — users whose payment activity stops according to the defined monthly payment-gap rule.
- **Churned Revenue** — revenue associated with users classified as churned.
- **Expansion Revenue** — increases in payment revenue from users with consecutive months of payment activity.
- **Contraction Revenue** — decreases in payment revenue from users with consecutive months of payment activity.

**Metric definition:** Monthly revenue is calculated from recorded payments in each calendar month. It is treated as an MRR proxy for this analysis and may not represent contractual recurring revenue.

## Tools & Technologies

- **PostgreSQL** — querying, data aggregation, and metric calculation.
- **SQL** — Common Table Expressions (CTEs), joins, date functions, conditional logic, aggregate functions, and window functions (`LAG`, `LEAD`).
- **Tableau Public** — dashboard development, data visualization, and interactive analysis.

## Data Sources

The analysis uses two tables provided as part of a data analytics course assignment:

### `project.games_payments`

Contains payment transaction information, including:
- `user_id`
- `game_name`
- `payment_date`
- `revenue_amount_usd`

### `project.games_paid_users`

Contains user attributes, including:
- `user_id`
- `game_name`
- `language`
- `has_older_device_model`
- `age`

The tables provide payment and user information for analysing revenue metrics and exploring differences between user groups.

## SQL Analysis

The SQL query prepares monthly revenue data at the user level and calculates revenue and user activity metrics.

The analysis includes:
- Aggregating payment revenue by user and month.
- Identifying each user's first recorded payment month.
- Comparing payment activity and revenue between consecutive months.
- Identifying users whose payment activity stops according to the defined churn rule.
- Aggregating the resulting metrics by month for visualization in Tableau.

The query is available in [`sql/revenue_metrics_analysis.sql`](sql/revenue_metrics_analysis.sql).

## Data Limitations

- The analysis is based on the dataset provided for a course assignment and may not reflect the performance of a real business.
- Monthly revenue is calculated from recorded payments and should not automatically be interpreted as contractual recurring revenue.
- Churn is inferred from gaps in monthly payment activity. A gap does not necessarily mean that a customer cancelled a subscription.
- Expansion and contraction metrics depend on the payment comparison rules implemented in the SQL query.

These assumptions should be considered when interpreting the results.

## Project Purpose

This project demonstrates practical skills in SQL-based revenue analysis, data preparation, metric calculation, and dashboard development. It also illustrates how structured data can be transformed into business metrics that support performance monitoring and analysis.
